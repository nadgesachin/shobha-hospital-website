# Shobha Hospital Multi Speciality, Khanvel — website

The website of Shobha Hospital Multi Speciality, Khanvel (a Suvacha Healthcare initiative), built as a fast static site for https://shobhahospitalkhanvel.com (shobhahospitalkhanvel.in and the old suvachahealthcare.in redirect to it). It needs Python 3 and Pillow, and nothing else.

```bash
python3 build.py --serve     # build into site/ and open http://localhost:8000
```

## Where things live

| Path | What |
|---|---|
| `content/site.json` | Clinic info: phone, WhatsApp number, address, hours, map, homepage text, FAQs |
| `content/services.json` | All 9 services (text scraped from the live site), with the doctors linked to each |
| `content/doctors.json` | All 11 doctor profiles |
| `src/css/style.css` | Design system (colours come from the logo) |
| `src/js/main.js` | Menu, "Open now" status, doctor filter, WhatsApp booking form |
| `src/img/` | Optimised WebP images (built by `tools/images.py`) |
| `build.py` | Generates every page into `site/` |
| `_original/` | Raw scrape of the live site: HTML, text and original images |
| `tools/` | One-off scripts for scraping and parsing (extract.py) and image optimisation (images.py) |

To change any text, edit the JSON and run `python3 build.py`. To deploy, upload the `site/` folder to any static host (Netlify, Vercel, cPanel, GitHub Pages).

URLs match the old WordPress site (`/service/<slug>/`, `/doctor/<slug>/`, `/about/`, …), so existing Google rankings and shared links keep working.

## Deploy

`netlify.toml` builds with `python3 build.py` and publishes `site/`. If the GitHub repo is linked in Netlify, every push to `main` deploys automatically. `site/_headers` and `site/_redirects` are generated by the build (security/caching headers and redirects for old WordPress URLs).

## Content added after the scrape

- `content/blog/*.md` holds the health-tip articles. Each file has front matter (title, description, date, category, image, service). Add a new `.md` file and rebuild.
- `content/reviews.json` holds Google reviews. While it is empty, the homepage shows a "Write a Google review" call-to-action instead.

## Languages (English, हिंदी, मराठी)

English is the source text, but **Hindi is the default language** and is served at the site root (`/…`). English lives under `/en/…`, Marathi under `/mr/…` and Gujarati under `/gu/…` (old `/hi/…` links 301 to the root). Every page except the 404 is built in all four languages: home, about, services and the 12 service pages, facilities, doctors list and the 11 doctor profiles, appointment, contact, pregnancy tools, and the blog with all articles. Doctor names, qualifications and the clinic address stay in English so they match the Google listing.

Translations live in `content/i18n/<lang>/`:

| File | What it holds |
|---|---|
| `site.json` | Translated fields of `content/site.json` (hero, about, FAQs, hours, …), with the same list lengths |
| `services.json` | Each service's title, tagline, intro and sections, keyed by slug |
| `seo.json` | Search titles, descriptions and service FAQs |
| `doctors.json` | Doctor specialities, roles, bios and profile sections |
| `blog/<slug>.md` | Translated articles: front matter `title`, `description`, `category`, then the body (date, image, sources come from the English file) |
| `strings.json` | UI phrases: English text → translation (buttons, labels, headings) |
| `js.json` | Text used by `src/js/main.js` (booking message, calculators, open/closed badge) |

After changing English text, run `python3 build.py`. Any English phrase still showing on a translated page is listed in `build/missing-<lang>.json`; add it to that language's `strings.json`. Run `python3 tools/check_i18n.py hi` (or `mr`, `gu`) to check that the translation files still match the English structure.
